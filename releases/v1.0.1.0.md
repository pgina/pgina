# OpenCredential 1.0.1.0

**Release estable de Desktop. El instalador NO tiene firma Authenticode.** La firma de confianza continúa pendiente de aprobación/integración del proveedor. Verifique el SHA256 antes de ejecutarlo y conserve un método de recuperación de Windows.

## Novedades

- Interfaz de configuración y ventanas de los ocho plugins oficiales en inglés/español, con distribución adaptable y mensajes de validación traducidos.
- Paquetes XML de idioma importables para configuración, con límites de tamaño, validación, respaldo regional y textos integrados. No se cargan scripts ni DLL desde un paquete.
- Textos nativos de inicio de sesión Windows en inglés/español, con selector independiente por equipo en General. LogonUI utiliza textos integrados y no carga XML externo. Se conservan credenciales, protocolos, mensajes personalizados y respuestas de los plugins.
- Instalador bilingüe, visor de registros traducido y ventana Acerca de con versión, licencia original, atribución a pGina y créditos a Yuri Mercedes Bermúdez Mazuera y Pedro Pablo Bermúdez Medina.
- Solicitud adicional de contraseña administrativa configurable desde General y **desactivada por defecto**. Se mantienen UAC y permisos administrativos; al activarla se exige reautenticación de la misma cuenta. No se guarda ninguna contraseña.
- Réplica offline completa y metadatos de sincronización atómicos; fallos, respuestas parciales/null o identidades duplicadas conservan la copia anterior. Un snapshot vacío válido revoca usuarios; MySQL desconectado ya no aparenta una copia vacía correcta.
- Estado de la copia local, sincronización manual y antigüedad máxima de 1–168 horas, con exclusión entre procesos y pruebas del primer acceso al motor de caché sin login previo en el equipo.

Incluye las correcciones de la RC: RDP/NLA y CredProtect, tipos de claves de grupos PostgreSQL, bloqueo UTC, reproducción del logger offline y preservación de configuración/datos al actualizar o desinstalar.

## Instalación y actualización

1. Descargar `OpenCredentialInstaller-1.0.1.0-unsigned.exe`, `SHA256SUMS` y `build-info.json` de **este mismo release**. Comprobar los checksums; los metadatos identifican el commit exacto de origen.
2. Respaldar configuración y datos persistentes. Mantener una cuenta administrativa local probada y un proveedor alternativo de Windows habilitado. Preferir primero un equipo piloto/VM con snapshot.
3. Cerrar la configuración y las conexiones RDP; ejecutar como administrador sobre la carpeta existente. No borrar cachés, registro ni datos persistentes para actualizar.
4. Revisar rutas de búsqueda de plugins si se migra desde una carpeta pGina. Guardar cambios y comprobar recuperación, autenticación y reglas de autorización antes de extender el despliegue.

Requisitos: Windows 10 21H2+ o Windows 11 22H2+, .NET Framework 4.8 y runtimes Visual C++ v14 incluidos. Versiones de archivo e informativa `1.0.1.0`; la identidad de ensamblados permanece en `1.0.0.0` por compatibilidad.

## Validación y límites

El propietario confirmó funcionamiento correcto tras ejecutar el instalador local con estos cambios funcionales y autorizó la publicación estable. Se recompila con el sello estable desde el commit publicado: el archivo final no es idéntico byte a byte al instalador local de prueba.

Se ejecutan regresiones locales de configuración/idiomas y ocho plugins, importación XML, licencia/créditos, acceso administrativo opcional, SQLite/DPAPI/caducidad/bloqueo/revocación, serialización nativa x64/Win32 e instalador. Las pruebas funcionales históricas en una VM Windows 11 cubrieron instalación, actualización, online/offline, logger, RDP/NLA, desinstalación y recuperación; no se afirman repetidas íntegramente para esta entrega.

Permanecen sin aceptación exhaustiva: Windows 10, extensiones de terceros, DPI reales/Narrador/NVDA/diseñador Visual Studio, primer login Windows offline integral de una cuenta nunca creada localmente y cambio de contraseña AdminWeb → login Windows. Una prueba del motor de caché no sustituye al gateway y login Windows completos. El plugin invitado temporal no está implementado. Los logs/SQL técnicos y mensajes de terceros conservan su idioma original; otros idiomas de LogonUI requieren compilación.

El release distribuye **solo Desktop**. AdminWeb y Docker Hub se gestionan por separado. Se conservan el prerelease `v1.0.1.0-rc.1` y los releases anteriores.
